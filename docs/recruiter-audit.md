# Recruiter-readability audit

## Hiring signal now

The portfolio presents a credible early-career software engineer with stronger-than-average exposure
to enterprise systems, customer constraints, backend integrations, cloud data workflows, and applied
AI. The promotion from intern to associate, work with three enterprise customers, and 100+ endpoint
SDK are the fastest proof points.

## What is working

- The opening identifies Frank as a software engineer without restricting him to field engineering
  or one narrow specialty.
- Professional evidence appears before a long technology inventory.
- Employer-owned work is clearly labeled and never implied to be public source code.
- Quantified facts are easy to find without reading every paragraph.
- Resume choices are explained, with the general software engineering version clearly recommended.
- Contact information and next actions are visible without a form or unnecessary interaction.

## Changes made during this audit

- Replaced broad phrases such as “practical applications” and “thoughtful systems” with concrete
  references to APIs, integrations, cloud workflows, delivery, and troubleshooting.
- Rewrote About around promotion, customer exposure, shipped systems, and prior operational
  management experience.
- Removed empty project categories and multi-card placeholder content that looked like evidence but
  did not represent completed work.
- Changed the primary title from “Full-Stack Software Engineer” to “Software Engineer” so backend,
  platform, integration, applied-AI, and full-stack roles all remain plausible.
- Changed the primary call to action to professional work until a public project is published.
- Added a reusable case-study format that gives recruiters the result first and reserves architecture,
  tradeoffs, testing, and reflection for technical reviewers.

## Current weakness

The portfolio still lacks public proof of independent engineering work. This is now communicated
honestly, but copy and design cannot replace a working repository and demo. One complete,
well-documented project will improve the hiring signal more than several small or unfinished projects.

## Standard for the first published project

- A working deployed product with one obvious primary workflow.
- A public repository that another engineer can run locally.
- A concise README with setup, architecture, tests, and known limitations.
- At least one meaningful technical challenge and an explained tradeoff.
- Automated tests focused on important behavior rather than test-count theater.
- A short demonstration and one strong screenshot.
- Verified outcomes stated without inflated or invented metrics.

## Recommended portfolio size

Feature two or three strong projects. The first should demonstrate end-to-end product delivery. The
second should emphasize backend, integrations, data, or reliability. A third is useful only if it
adds a meaningfully different signal, such as applied AI or developer tooling.
